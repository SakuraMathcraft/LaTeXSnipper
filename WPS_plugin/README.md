# LaTeXSnipper WPS 插件

本目录是 WPS 插件的开发和贡献入口。完整交付覆盖 Windows 和 macOS 的 WPS 文字、WPS 演示。以现有 Windows Office 插件为功能基准，逐项保留目标宿主可实现的功能，并沿用现有文档数据契约。采用替代方式前，记录实际的宿主限制和验证结果。

## 目录与架构

| 目录 | 职责 |
| --- | --- |
| [`shared/`](shared/README.md) | WPS 文字、演示的共用界面与工作流、公式元数据读写和测试样本 |
| [`windows/`](windows/README.md) | Windows 的 WPS 加载入口、平台适配、安装和实机测试 |
| [`macos/`](macos/README.md) | macOS 的 WPS 加载入口、平台适配、安装和实机测试 |

复用 [Office 插件公共资源](../Office_plugin/shared/) 中的公式编辑器、符号与模板、MathJax 排版适配器。WPS 宿主操作集中在文字和演示各自的适配层。不同操作系统共用的实现归入 `shared/`，安装、权限和本机桥接按平台管理。Windows 与 macOS 使用同一套文档契约和测试样本。

通过目标 WPS 版本公开支持的加载项接口操作活动文档、选区、公式、域和形状。平台适配层只处理宿主差异，公式数据随文档保存。WPS 插件的安装、构建、测试和发布均由本目录管理。Microsoft Office 插件的源码、桌面端源码及其发布流程保持固定。

## 公式后端

| 平台 | WPS 文字 | WPS 演示 |
| --- | --- | --- |
| Windows | 默认 OLE，可选 OMML | 默认 OLE，可选 PNG |
| macOS | OMML | 默认 PNG，可选 SVG |

Windows 的 OLE 公式复用 LaTeXSnipper 已有的 Windows 本机对象组件、`LaTeXSnipper.Formula` 类和文档存储契约。WPS 与 Microsoft Office 在同一份文档中双向保留新建、加载、双击编辑、修改和保存能力。OMML 和 PNG 同时提供跨操作系统的文档编辑路径。macOS 对已有 OLE 保留对象及其文档内容。

## WPS 文字

- 保留行内、行间、带编号插入，加载、编辑和删除所选公式，所选及全文解析，所选及全文格式化。Windows 支持 OLE 双击编辑和 OLE／OMML 显式互转。macOS 的新公式使用原生 OMML。
- 支持自动编号、手动编号、给已有公式添加编号、重编号、交叉引用、章／节分隔符。保留编号位置、外框、层级前缀、隐藏分隔符仍参与计数及多栏排版。沿用原生 `SEQ`、`REF` 域及书签保持引用可更新。
- 解析使用现有 LaTeX 定界规则，覆盖正文及表格单元格。保留行间公式的 `\tag{...}` 手动编号。批处理支持进度、取消和重试，转换失败的公式保留原文。
- OMML 沿用现有 Word 托管公式的内容控件短标签及文档变量。OLE 沿用现有嵌入对象的数据、矢量预览和 Word 实例标记。加载、编辑、保存和重开时保留原始 LaTeX、样式、实例身份和编号。普通编辑沿用原有样式，主动格式化应用设置中的样式。

## WPS 演示

- 独立公式居中插入。各平台的两种后端均支持插入、加载、编辑、删除、所选及全文格式化，以及显式互转。Windows 的 OLE 公式支持双击编辑。
- 沿用现有 PowerPoint 形状标签保存完整源码、样式、实例身份和自然尺寸。OLE 同时保留嵌入数据和矢量预览。Windows 的 OLE 和 PNG 均与现有 PowerPoint 插件双向编辑，macOS 的 SVG 保留矢量格式和可重新加载的源码。
- 普通编辑保留原格式、位置、缩放和图层顺序。显式转换保留位置、缩放和层次。主动格式化按设置重绘并恢复自然尺寸，保留位置与层次。
- 将已有文本框光标处插入原生公式纳入 Windows WPS 的能力验证。支持该操作的宿主应保留原生编辑、文字排版和字号继承。记录每个平台的实测结果，保护选区内已有文字。

## 共同工作流与文档保护

- 两个宿主提供中英文功能区、状态窗格、公式预览、可视化与源码编辑、符号模板和收藏、公式样式、JSON 预设及帮助。使用共用编辑器和宿主提供的选区与文档状态。
- 插件独立安装和运行。输入、渲染、加载、编辑、格式化和设置在本机完成。只有截图识别调用现有 [Automation API](../docs/automation_api.md) 的 `next_result` 订阅、查询和取消，截图由用户通过桌面端发起。会话令牌由本机调用方保管。
- Windows 只将通过类标识和元数据校验的 LaTeXSnipper OLE 纳入编辑。macOS 只识别已有 OLE 的对象类型，选中时提示回 Windows 编辑，文档写入跳过 OLE。各平台的插入、删除、格式化、转换、解析和重编号均保护混合选区中的非目标对象。
- 普通编辑只更新已确认的目标。损坏或不受支持的元数据应提示并保留原对象。文档契约和操作语义见 [Office 公式工作流](../docs/Office_plugin_formula_workflows.md)。

## 验收与贡献

1. 在目标系统上记录 WPS 的版本、版本类型、支持的加载项入口和安装／卸载步骤。实测功能区、任务窗格和保存重开，以实测结果确定支持范围。
2. WPS 文字和演示分别验证桌面端关闭时的公式工作流，以及桌面端开启 Automation API 后的 OCR 订阅、结果处理和取消。覆盖错误、取消和批量操作。
3. 在 Windows 分别从 WPS 与 Microsoft Office 创建含 OLE 公式的 `.docx` 和 `.pptx`。两种来源的文件都在另一个宿主中双击编辑、修改、保存并回到原宿主重开。核对源码、样式、预览、实例身份、Word 编号引用和演示的位置、缩放及层次。覆盖 Windows WPS 的格式互转。
4. 用现有 Windows Word 插件生成的 OMML `.docx` 和 PowerPoint 插件生成的 PNG `.pptx` 验证跨操作系统往返。WPS 加载、修改并保存后，回到 Microsoft Office 插件继续编辑，再由 WPS 重开。验证 macOS 编辑并保存 SVG 后仍保留矢量格式和元数据。
5. 用含既有 OLE 和可编辑公式的混合文档验证 macOS 保存重开。回到 Windows 后，保留的 OLE 仍可双击打开。覆盖 Windows 和 macOS 的非目标对象保护。
6. 提交可复现的构建、安装和测试步骤，以及已实际编辑过的 `.docx` 和 `.pptx` 样本。标明验证平台、WPS 版本、公式位置和预期 LaTeX。公开接口存在限制时，记录对应版本、测试步骤和可观察结果。

实现保持简洁、模块化，复用现有资源和当前元数据契约。使用可解析的相对路径、显式 UTF-8 和严格协议解码。Python 代码使用 `latexsnipper.<module>` 日志命名并在宿主入口统一配置日志。清理废弃逻辑及过时测试，避免兼容层、迁移逻辑和只验证删除结果的测试。Git 提交信息、PR 标题和说明使用英文。更新对应的权威说明，区分已验证和待验证的能力。
