# Office 插件字体、编辑体验与预设重构方案

日期：2026-09-12

状态：第 1—6B 步实现完成；下一步为 6C 编辑器交互收尾。第 4 步剩余 Office OLE 实机检查按用户确认并入第 8 步安装包发布验收（2026-09-23 更新）。

适用范围：Word / PowerPoint Office 插件；客户端共享 MathJax 运行时升级与导出边界

## 1. 本次更新的明确边界

本次统一公式字体、字号、最终效果预览、源码编辑和预设保存。保留现有 Office 宿主、MathLive 编辑器及 MathJax 渲染架构，不重写插件。

- **MathJax 升级阶段已完成：客户端与插件统一为 4.1.3。** 共享版本清单、配置和转换接口，按用途打包、独立运行；已删除 v3 资源。客户端资源约 6.77 MiB，插件约 5.40 MiB。维护与验证记录见 [运行时维护说明](../tools/mathjax/README.md)，后续不重复进行版本选型或体积评估。
- **OMML 与 OLE / PNG 共用样式配置及格式化入口。** OMML 适配器将可表达的字体、字号和字形属性映射到 MathML / OMML 或 Word 对象属性，最终取字、回退和排版由 Word 决定；不承诺与 MathLive 或 OLE 像素一致。
- 字体系统覆盖 Word OMML / OLE、PowerPoint OLE / PNG；OLE / PNG 提供最终效果预览，OMML 提供参考预览。
- 源码编辑体验适用于共享公式编辑器；OMML 模式不显示承诺与 Word 一致的字体预览。
- 本次提供符号字体、数字字体、汉字字体、字号、颜色和预设。正体、斜体、粗体等保留为字形样式，不能与字体家族混为一项。
- **不兼容或迁移旧文档、旧公式和 schema 2，不保留旧渲染、旧字号或旧包装逻辑分支。** 用户允许本次破坏性协议更新；用户主动提供的合法 LaTeX 仍按新链路解析。
- 不实现完整 TeX 引擎，不自建完整 LaTeX 解析器，不追求任意系统字体替代全部数学符号。
- 不改变公式身份、编号、引用和用户正文；未经明确指令不提交或推送改动。

本方案描述目标架构与分阶段实施记录。`office_plugin_formula_workflows.md` 随已落地阶段更新当前源码、样式与元数据边界。

## 2. 现状与已确认的问题

| 位置 | 当前实现 | 对本次工作的影响 |
| --- | --- | --- |

## 3. 核心设计：源码与样式分离

### 3.1 唯一数据流

```text
原始源码 + 公式样式快照 + 输出上下文
    → 单一 MathJax 运行时解析
    → 节点样式解析与字体度量
    → 布局与 SVG 输出
    → 必要文本轮廓化，生成可移植的最终矢量结果
    ├─ 最终效果预览
    ├─ EMF → Word / PowerPoint OLE
    └─ PNG → PowerPoint
```

MathLive 保留可视化编辑功能，不充当最终输出的唯一判断依据。OMML 复用源码解析与样式解析结果，走“语义 MathML → OMML → Word 属性应用”适配器；不经过 SVG 轮廓化，也不为追求相同字形引入另一套源码包装规则。

统一的是样式意图、优先级和操作入口；各输出后端负责表达同一意图。无需为 OMML 复制设置页或维护平行预设，也不能因为后端不同而跳过整个格式化命令。

### 3.2 样式优先级

1. 源码显式局部样式优先，例如 `\mathbf{A}`、`\mathrm{d}`、`\textcolor{red}{x}`。
2. 公式自身的完整样式快照为未显式指定的节点提供默认值。
3. 用户当前预设只用于创建新公式，或用户主动对已有公式应用预设。
4. 内置默认配置仅补充缺失字段，不覆盖用户已有有效配置。

预设中的字体家族负责字形来源，源码中的正体、粗体、花体等负责数学样式语义；不把两者压缩为一个枚举。

普通“格式化所选 / 全文”更新样式快照并重新渲染，不改写原始源码，不删除局部样式。清除源码显式格式不是本次普通格式化的隐式行为；若后续提供，应是独立命令。

数学结构通过 MathJax 的解析树处理，不再靠在环境外包裹 `\mathrm{...}` 实现默认字体。字体处理必须在相关字形度量与布局前生效，不能只对已排版的 SVG 更换字体名称。

## 4. 共享数据契约

共享契约已在 Abstractions 实现，正式渲染及宿主已接入；后续界面和预设工作按第 11 节执行，职责不得分散到宿主控制器。

### 4.1 FormulaTypography

不可变样式对象，至少包含：

| 字段 | 含义 |
| --- | --- |
| `SymbolFontId` | 稳定的数学字体方案 ID，不使用本地化显示名称作为键 |
| `NumberFontFamily` | `null` 表示跟随符号字体，否则为独立数字字体家族；实际可用性由字体解析服务确认 |
| `CjkFontFamily` | 汉字及约定中文标点的字体家族 |
| `DefaultMathStyle` | 默认数学字形样式，与字体家族分开 |
| `FontSizePoints` | 插入时已经解析出的实际字号；产品接受 1–1638 pt 的有限数值，支持小数 |
| `Color` | 统一为 `#RRGGBB` 的默认公式颜色，显式局部颜色仍优先 |
| `TypographyVersion` | 样式契约版本 |

持久化保存用户请求的字体；渲染结果另附实际采用的字体、缺字与回退诊断。不能因为临时缺字或当前机器缺字体就静默覆盖原设置。

### 4.2 新建默认值与公式快照

预设允许字号模式为“固定 pt”或“跟随宿主”。新建 Word OLE 时在确定插入上下文后解析 Word 字号；PowerPoint 只在存在有效文字上下文时跟随，否则使用明确的默认 pt 值，并在界面显示。

公式一旦插入，就保存实际 `FontSizePoints`。重新加载或更新时不得重新读取当前光标字号并改变公式。用户手动拉伸对象的比例单独作为宿主几何状态管理，不能反写为公式字号。

新建时允许保留用于预览的已解析上下文；若提交时宿主上下文发生变化，需要刷新最终结果，确保插入采用的字号与最后确认的预览一致。

### 4.3 FormulaMetadata 与渲染请求

- 新增完整 `Typography` 快照，目标 schema 3。
- 保留原始 `Latex`、身份、显示模式、编号等既有字段与职责。
- 预设 ID / 名称只作为可选来源信息；重绘不得依赖本机仍存在该预设。
- `RenderRequest` 显式接收样式快照，宿主不再先加工一份带默认包装的源码。
- 缓存键包含源码、显示模式、完整样式、字体资源版本、实际字体解析上下文、渲染器版本及必要输出参数。
- 字体配置相同但本机实际字体不同，不得错误复用缓存。
- 重新渲染判断比较完整样式，不再只比较 Latex 和 FontScale。

## 5. 单一 MathJax 字体实现

### 5.1 字体能力范围

- 符号字体先保留现有 TeX 数学字体作为完整基底，已有正体、粗体、无衬线等选项重新归类为字形样式。
- 只有具备必要数学字形、度量和拉伸规则且通过验收的字体方案，才进入符号字体列表。第一版不虚构未实现的系统数学字体支持。
- 数字字体独立处理数学数字节点；遵循局部样式、上下标缩放与布局度量。文本节点内数字仍属于文本，避免破坏普通文本语义。
- 汉字字体覆盖汉字和明确约定的中文标点；混合文本按字符类别切分为字体运行段，保持文字顺序、空格和基线。
- 非中文文本沿用明确的默认文本字体方案，不额外增加用户设置项。
- 字形缺失按统一顺序回退，并通过最终预览提示实际字体；禁止静默宣称已应用不可用字体。

### 5.2 适配器设计

在 Rendering 中集中实现MathJax 4 字体适配器，利用现有解析节点及输出扩展点应用默认样式和测量结果。所有与 MathJax 内部节点、variant 或 wrapper 的耦合必须限制在此处，并固定版本和回归用例。

独立数字字体与 CJK 字体需要共享字体解析、文字测量及轮廓生成能力。可在现有 Windows 字体绘制基础上实现一个度量和轮廓服务，让布局使用的字符宽度与最终轮廓采用相同字体来源。缓存以字体、样式、文本运行段等为键，避免按字符频繁跨 WebView 调用。

不允许“浏览器按 A 字体测量、EMF 按 B 字体画字”。对于需要系统字体的文本，最终矢量结果必须使用已确定的字体和字形；轮廓化后的预览与输出共用同一份几何数据。

正体希腊字母采用集中、可测试的 variant 兼容规则；先观察 `\mathrm{\delta}` 的解析结果，再决定节点映射或字形选择。不能全局字符串替换所有希腊命令，也不能让普通 `\delta` 一并变成正体。

### 5.3 实施前的最小技术验证

基于已经完成升级的 MathJax 4.1.3 验证以下三个字体垂直样例，结果作为字体模块实现依据。复用现有 WebView2、Qt WebEngine 与 EMF 回归入口，只补充字体能力验证，不重复运行时升级：

1. `align` 内默认字体覆盖、局部样式优先、嵌套矩阵结构不变。
2. 正体 / 斜体希腊字母经过 SVG 和 EMF 后保持预期字形。
3. 独立数字字体与两个可用中文字体切换，宽度、基线、分式和上下标不重叠、不裁切。

MathJax 4 已通过体积与本地资源加载验证，但尚未证明可替代所有字体适配工作。若 v4 的公开扩展点不足，只在字体适配器内补充版本限定实现；若仍不能满足某字体的排版要求，明确该字体暂不支持，并记录具体阻碍，不能用视觉替换掩盖错误。

## 6. 字号与输出尺寸

- 内部使用 pt；界面提供可编辑组合框，接受数字和中文字号别名，支持小数。
- 标准别名集中定义：初号 42、小初 36、一号 26、小一 24、二号 22、小二 18、三号 16、小三 15、四号 14、小四 12、五号 10.5、小五 9、六号 7.5、小六 6.5、七号 5、八号 5.5。
- 校验范围由共享契约统一定义并显示错误；不静默恢复成默认字号。拒绝 NaN、无穷和非正数。
- 以目标 pt、渲染字体 em 度量、SVG 坐标体系统一计算自然宽高与基线；移除新链路中的固定 ex 经验值和重复倍率。
- 多行公式的总高度由布局决定，不能通过把对象总高度设为 12pt 来实现 12pt 字号。
- 编辑器视觉缩放、公式实际字号、宿主手动对象缩放三者分开。
- 普通编辑保留宿主已有手动缩放；主动格式化恢复目标样式对应的自然尺寸，沿用清晰一致的命令语义。
- PNG 的像素数由自然 pt 和输出 DPI 计算；更改 DPI 不改变插入物理尺寸。

## 7. 编辑器与最终预览

### 7.1 源码编辑

将 textarea 替换为本地打包的 CodeMirror 6，通过小型 `SourceEditor` 适配层封装读取、事务更新、选择、诊断与焦点控制。Word / PowerPoint 共用实现，不引入完整 IDE 或在线资源依赖。

统一颜色 token：命令、环境名、数学符号、数字、括号层级、对齐符 / 换行、注释、文本内容、错误。提供明暗两套主题，兼顾对比度，正文文字不做无意义彩虹着色。

本次包含括号匹配、自动缩进、撤销重做、查找替换、基础命令 / 环境补全及错误定位。中文输入法组合期间不执行会打断输入的源码重写。

### 7.2 源码与 MathLive 同步

- 原始源码是持久化内容依据，程序更新 MathLive 不触发反向覆盖。
- 记录编辑来源和修订号，消除延迟同步任务覆盖较新源码的问题。
- 只有用户实际在 MathLive 编辑时才接受其序列化结果，单纯加载、预览和失焦不改源码。
- 对不能可靠往返的环境保留源码编辑与最终预览，禁用会破坏源码的可视化编辑并给出简短提示。
- 源码和可视化修改共享文档修订边界；模式切换不清空撤销历史，程序同步不制造重复撤销步骤。

### 7.3 最终效果

编辑区提供“可视化编辑 / 最终效果”切换。新建公式即获得预设的完整上下文；最终效果调用共享渲染服务，显示经过字体解析和必要轮廓化的结果。

预览请求使用防抖、取消及修订号检查，旧请求不能覆盖新结果。提交必须使用当前源码和样式对应的有效结果，或等待同一请求完成；不得直接插入上一版预览。

字体回退、语法错误和当前预览过期均显示明确状态。预览错误时保留源码，不把错误占位图当成公式插入。

最终矢量几何相同是 OLE / PNG 一致性的标准；浏览器与 Office 的抗锯齿差异不作为字体不一致。EMF 转换仍需实际 Office 验证。

OMML 模式保留相同字体面板和格式化命令，预览标示“参考效果，实际排版由 Word 决定”。执行后保持 OMML 类型，不自动转换成 OLE。

OMML 适配器将解析后的有效样式映射到支持的节点属性或 Word 公式范围属性，避免覆盖周围正文、编号与引用。插件数学字体资源 ID 不等于 Windows 字体家族名；两者通过集中字体目录映射，无法对应时由 Word 使用其数学字体机制，不添加仿真分支。字体或字形无法表达时返回结构化的“不支持 / 由 Word 决定”结果，不伪报属性已经写入。

本次验证聚焦：支持的属性正确写入、公式结构与内容不变、重复格式化稳定、失败可诊断。不同 Office 版本的具体取字和视觉差异不作为插件修复或跨渲染器像素对齐目标。

## 8. 设置与预设

建议存储目录：

```text
%APPDATA%/LaTeXSnipper/OfficePlugin/
    settings.json
    typography-presets/
        <stable-id>.json
```

内置预设随程序只读发布；用户预设存于上述目录。WebView 缓存和临时渲染文件继续放 LocalAppData，不用 localStorage 保存核心字体配置。

- 提供保存、另存为、加载、删除用户预设、导入、导出和设为新建默认值。
- “加载预设”只改变当前编辑草稿；“设为默认”影响后续新建；“应用所选 / 全文”才改变既有公式。
- 预设包含字体、字号模式、颜色，不混入 Word 编号与 PowerPoint 插入方式等宿主选项。
- 保存采用同目录临时文件与原子替换，保留可恢复备份；多个宿主写入需串行化并避免覆盖对方字段。
- 导入校验 schema、字段类型、字号和字体描述；不接受脚本、宏注入或任意资源加载路径。
- 未安装字体保留用户原选择并显示回退情况；不能以“导入成功”掩盖字体缺失。
- 安装升级不覆盖用户目录，不通过注册表默认值写入清空已有配置。
- 配置读取失败保留损坏文件并提示恢复来源，不自动用默认值覆盖唯一副本。

Word 与 PowerPoint 使用共享预设仓库；各自保存选中的默认预设 ID，避免在一个宿主选择新默认值时意外改变另一个宿主。

## 9. 单一协议与用户配置保留

### 9.1 公式协议一次切换

只支持新的 schema 3。共同更新 FormulaMetadata、Word Document.Variables JSON、PowerPoint 分块元数据及原生 OLE payload，托管层与 x86 / x64 handler 同步发布。

删除旧 schema 读取、FontScale 恢复、旧自然尺寸推断和源码包装迁移，不提供旧版渲染后备路径。旧数据或未知协议只在入口统一拒绝编辑并提示“不支持该公式版本”，不删除对象、不猜测转换、不静默重建。

新公式必须在 OLE 激活、重新编辑、复制粘贴与宿主间转换中完整保存源码、样式快照和矢量呈现。现有旧公式的显示不作为新版验收承诺；不为其增加实现分支。

### 9.2 用户预设跨更新保留

## 13. 客户端与插件统一升级、保留导出职责

### 13.1 已确认的四点结构

1. 一份版本锁定和声明式资源清单：MathJax、字体和扩展有固定版本与完整性记录。两端升级至同一 v4，不保留“客户端 v3、插件 v4”的长期分叉。
2. 一套共享 JavaScript 配置基础与转换接口：统一扩展集合、字体资源定位和必要语义处理；Python / C# 仅保留各自 WebEngine / WebView2 消息桥接，不重复维护规则列表。
3. 两个声明式打包配置：客户端包含 CHTML + SVG 及 MathML 转换能力，插件包含 SVG 及 MathML 转换能力。CHTML 属于客户端真实需求，不能直接使用插件的 SVG 精简包替换客户端目录。
4. 两端独立安装运行：共享资源来源和构建逻辑，各安装包携带所需子集；插件运行时不依赖客户端的安装路径和版本。

当前客户端的普通、混合内容和智能预览加载 CHTML，导出转换使用 SVG / MathML。客户端保持现有预览输出类型，不为统一版本强制将所有预览改成 SVG。

当前实际资源为客户端约 6.77 MiB、插件约 5.40 MiB，包含共享适配器及资源清单；这是资源目录大小，不是安装包压缩体积。Qt WebEngine、WebView2 和 EMF 运行验证已经完成。

### 13.2 当前客户端导出依赖审计

源码依据：`src/exporting/formula_export.py`、`formula_converters.py`、`formula_format_helpers.py`、`pandoc_exporter.py` 和 `src/ui/editor_actions_controller.py`。

| 导出项 | 导出时的路径 | 阅读输出时是否需要 MathJax |
| --- | --- | --- |
| LaTeX 行内 / display / equation | 源码规范化外层定界符，再按格式包装；不调用 MathJax | 由接收方决定，与客户端导出无关 |
| Markdown 行内 / 块级 | 保留公式源码并加美元定界符；不调用 MathJax | 由 Markdown 阅读器决定 |
| MathML 及其 mml / m / attr 变体 | 本地 MathJax → MathML → 标准化 / 命名空间处理 | 输出不自带 MathJax，由阅读器处理 MathML |
| 普通 HTML（`html`） | 本地 MathJax → MathML → span 包装的 HTML 片段 | 片段不附带 MathJax 脚本，依赖接收方的 MathML 支持 |
| Word OMML（`omml`） | 本地 MathJax → MathML → Microsoft MML2OMML.XSL → OMML | 不需要 MathJax，由 Word 排版 |
| SVG Code（`svgcode`） | 本地 MathJax → 独立 SVG | 不需要 MathJax 运行时；外部字体或文本回退仍需按输出内容考虑 |
| Pandoc HTML 独立页 | Pandoc `--standalone --mathjax`，没有调用本地 MathJax 转换器 | 需要 MathJax 排版公式；现有脚本通常引用 CDN，不等于离线自包含 |
| Pandoc DOCX / PPTX / ODT / EPUB / Typst / plain | Pandoc 转换源码，不调用本地 MathJax 转换器 | 由输出格式与阅读器决定，不由本地 MathJax 运行时负责 |
| Pandoc PDF | Pandoc + 已配置 / 探测到的 LaTeX 引擎 | PDF 阅读不需要 MathJax |

Pandoc 的所有格式统一进入文件保存流程，包括 HTML 独立页（`.html`）、Typst（`.typ`）与纯文本（`.txt`）。文本文件使用 UTF-8 编码；后台转换后保存，取消保存不执行转换。普通 HTML 片段继续使用原有文本导出流程。

普通 HTML 与 Pandoc HTML 独立页是不同的导出路径。当前 Pandoc HTML 已使用精确版本脚本参数，并由共享加载器提供 4.1.3 配置；已移除浮动 `@4` 地址。

### 13.3 共享运行时与样式职责

**共享 MathJax 不意味着共享用户样式覆盖。** 客户端导出默认不注入 Office 插件预设、当前 Word 字号、界面主题颜色或预览缩放。插件传入自身公式样式快照；客户端传入源码及自身明确的导出选项。两者使用同一转换服务，参数来源不同，不建立两份转换实现。

当前转换接口已经按请求输出 MathML 或 SVG；后续保留这一接口，不恢复每次强制同时转换的路径。
